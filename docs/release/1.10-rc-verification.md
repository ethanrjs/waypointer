# Release candidate verification

## Initial integration

Candidate merge `2f98eb3` contains `origin/feat/codec-v10` (`68ba1fa`),
`origin/feat/new-renderer` (`acb584c`), Crystal Hollows (`44f8714`), and the
initial issue fixes through `06db9b1`. `origin/beta` and `origin/main` are
ancestors; neither branch was changed.

Baseline `build` passed on both 26.1.2 and 26.2 with Java 25 and two workers,
including tests, coverage thresholds, and the documentation version gate.
No stale-documentation override was used. These are baseline results;
final candidate results are recorded separately below.

## Minecraft 26.1 compatibility evidence

Fetched the official 26.1 client using Mojang's version manifest. Verified
SHA-1 `191771837687b766537a8c4607cb6fad79c533a1` against that manifest.
Applied the existing Waypointer and Fabric access wideners using Fabric's
AccessWidener implementation, then compiled the complete 26.1.2 client
source set against the 26.1 client instead of the 26.1.2 Minecraft jars.
The compile passed. The first compile without access widening produced only
access errors for the intentionally widened Minecraft members; no missing
Minecraft symbols or changed method signatures were reported.

This confirms the checked client source's Minecraft API compatibility.
It does not prove a 26.1 game launch, mixin application, compatibility with
every Fabric API version, or rendered output. Runtime checks remain necessary.

## Checks required before publication

- Final full builds/checks on both supported build targets.
- Fresh launcher profile: reuse publisher identity and name; preserve a
  different identity in an existing profile. No actual user credentials are
  read by automated tests; they generate disposable keys in temporary folders.
- Rapid export-option changes; paste each supported format; import foldered
  colored routes; open the imported route; cancel/reopen export screens.
- Renderer: normal and painted routes; previous/current/next colors; edits,
  progression, distance limits, block-shape changes, disconnect/rejoin,
  resource reload, resize, and Iris enabled/disabled.
- In-game CPU/GPU frame-time comparisons with identical scene, view, shader,
  route count, and configuration. Offline CPU microbenchmarks are not FPS proof.
- Hypixel Crystal Hollows lobby switches, Wishing Compass particle captures,
  and mineshaft import targeting.

## Measured CPU and encoding results

Measurements use Java 25 in the same JVM per comparison, with the normal test
instrumentation enabled. They describe these workloads, not total game FPS or
network publication latency.

| Workload | Result |
| --- | --- |
| Nine unique saved routes, full-fidelity V9 vs V10 | 7,758 -> 5,689 ASCII characters, 26.67% shorter; all nine improve. |
| Same routes without names | 2,923 -> 2,694 characters, 7.83% shorter. |
| Same routes, coordinates only | 2,775 -> 2,633 characters, 5.12% shorter. |
| 8,000-point publish preparation, 5 warmup pairs and 20 alternating measured pairs | Strict round-trip median 186.777 ms; prepared manifest median 91.979 ms; 2.03x faster. |
| 1,024-marker scene key, 100 warmup and 1,000 measured samples | Median 0.056 ms, p95 0.065 ms, maximum 0.153 ms. |
| 2,000 camera positions alternating across a 16-block boundary, unchanged visibility/geometry | Previous origin rule: 2,000 rebuilds; retained origin: 1 rebuild. |

Saved route files were copied to a temporary fixture directory before inspection;
no launcher configuration or waypoint store was modified. Reproduce the synthetic
CPU workloads using `test --tests '*CatalogPublishPreparationTimingTest'
--tests '*RendererSceneKeyTimingTest' -Pcatalog.publish.timing=true
-Prenderer.timing=true --info`. The existing `V10LengthReport` accepts a fixture
directory via `-Pv10.routes`.

The optional hostile-frame timing test previously mutated arbitrary compressed
bits, including unused padding that can legitimately preserve valid semantic
content and its checksum. It now tests 20,000 distinct invalid checksum values
on a valid compressed frame, forcing decompression followed by checksum rejection.
The separate existing transport tests still accept valid alternate DEFLATE streams.
No production codec bytes or checksum rules were changed for this correction.

The corrected V10 timing run passed: 1,080 selected frames, encode median
0.192 ms / p95 2.024 ms, decode median 0.155 ms / p95 1.389 ms. All 20,000
invalid-checksum compressed frames were rejected; median rejection 0.027 ms,
p95 0.033 ms. Run with `test --tests '*V10ProductionTimingTest'
-Pv10.timing=true --info`.

## Final automated gate

`buildAllTargets --max-workers=2` passed after the complete reviewed code changes,
with separate successful builds/checks for 26.1.2 and 26.2. The final suite contains
1,758 tests: zero failures/errors, nine expected platform/opt-in skips. The
performance checks above were separately enabled and passed.

Coverage for the existing gated class set is 56.247% lines and 48.419% branches,
above the unchanged 52% / 44.5% thresholds. The renderer branch's existing GPU-only
exclusions remain; these percentages are not evidence of live GPU behavior.
Both packaged JARs were inspected for the intended Minecraft version ranges.

The release branch also runs this full gate in GitHub Actions, with the remote
locale manifest pinned to the exact source commit. Check the run attached to the
candidate commit for authoritative remote CI status. No release has been published.
