# Independent V10 codec shortening review

Review date: 2026-09-04. Base: `8e85aea`. Worktree: `perf/codec-route-benchmark`.

**Final verdict:** no remaining actionable correctness or compatibility issue was identified in the submitted compact-common eligibility change or benchmark. The reviewer did not change production code or run Gradle. Independent checks used Java 25 with a 256 MiB heap and separate temporary class directories; the parent task owns the integrated Gradle gate.

## Production patch

The change in `V10CompactRouteCodec.java` adds an encoder choice for exactly one additional export field set: names, colors and zone enabled; radii, optional flags and group metadata disabled; empty label. It admits only regular routes whose omitted fields already match the existing general projection.

The gate checks MANUAL color mode, SEQUENCE load, default group radius and palette settings, skip-ahead enabled, zero custom point radii, and that projected flags and precision equal the source values. The 24-bit color condition is a conservative restriction on this new path. Existing compact eligibility still checks bounded names, zone, count, deltas and temporary state. The selected representation uses the unchanged canonical full subtype. No source fields, decoder rules, entropy descriptors, compression strategies or no-names canonical choices changed.

These details matter:

- Optional visual flags cannot silently survive a flags-off request. Required subwaypoint, disabled and color-lock behavior remains governed by the existing projection helpers.
- Custom subwaypoint precision remains eligible because the existing general projection retains it. Ordinary custom precision that would be discarded is ineligible.
- A nondefault group palette field remains ineligible even in MANUAL mode, because the full body could otherwise preserve metadata that the request disabled.
- The existing full-fidelity and no-names paths retain their previous eligibility and canonical encoding behavior.

The new tests compare all decoded waypoint record fields and group metadata against the existing general codec, assert that the source is unchanged, and cover required flags/precision and excluded metadata, option sets and temporary points. The CODEC.md eligibility and subtype descriptions now agree with the implementation.

### Independent patch checks

An 80-case adversarial matrix included empty and one/two/three-point routes, negative coordinates, varied names and RGB values, required flags, subwaypoint precision, nondefault group metadata and discarded point fields.

- 32 cases were eligible for the new compact candidate.
- 48 cases preserved the exact existing general fallback text.
- Every decoded waypoint record and group metadata field matched the old general projection.
- Source groups and waypoint lists were unchanged.
- No selected share became longer.

The reviewer also compiled `V10CompactRouteCodec.java` from baseline commit `8e85aea` into a separate class directory. That original compact decoder accepted all 25 newly selected compact shares produced by the matrix. This is direct compatibility evidence in addition to the unchanged decoder diff.

These checks are bounded, not an exhaustive proof over every possible route or malformed frame. Existing conformance tests and the integrated codec suite remain part of the release gate.

### Fairness and interpretation

- Every production sample is decoded and checked for exact ordered block and precise coordinates. Common metadata additionally checks group name, mapped zone, point names and RGB. Unexpected failure aborts instead of becoming a small or silently omitted successful row.
- The primary size is the complete UTF-8 share string, including prefixes, checksums, compression framing and escaping. Java UTF-16 character counts and Unicode code-point counts are reported separately.
- Common peer label sanitization, blank-name substitution and group-name fallback are applied equally to both inputs and disclosed. Native full fidelity preserves the normalized source model and original source names; raw decimal RGB and source provenance are outside that model.
- Unsupported peer islands remain explicit rows excluded from both sides of matched totals. Skytils V1 is supported for 50 of 302 routes; 252 are unsupported. The benchmark does not substitute an island.
- The dataset SHA-256 is `2179ccf560c24291fa706cdbf8b89c2d36fc526560040bfa717a30675a3d21d7`, with 302 records, 31,418 points, 302 distinct normalized metadata records and 298 distinct ordered geometries. Its counts match the previously used locked corpus. The new split is retrospective reporting, not established unseen evaluation data.
- Geometry duplicates stay in the same split. Deduplicated coordinate summaries retain the first source occurrence, so peer costs that include mandatory names/islands can depend on input order. Two duplicate pairs differ in Skytils eligibility, and one pair differs in Skyblocker size. This is disclosed; source-weighted totals retain every record.
- There are no real one- or two-point routes. Those sizes occur only among explicitly separated derived prefixes. Real short-route claims begin at three points.
- SkyHanni means Waypointer's current raw JSON writer, not every encoding a SkyHanni release may accept. Skytils means the production V1 gzip writer, not V2 Brotli. No strongest-peer or universal-format claim follows.

The initially fragile benchmark format classifier used a V10 first-byte peek as if it verified the envelope. It now takes the explicit legacy path or checks the production decoder version before probing V10. A failure on this particular corpus was not established; the correction removes reliance on compressed leading bits.

## Generic compression controls

`tools/codec-compression-controls.mjs` includes Base64 text size and verifies both compressed-body equality and reconstructed ordered coordinates for every row. Gzip retains its standard header/checksum. Brotli intentionally lacks the Waypointer version, prefix and CRC envelope, and this advantage is expressly disclosed. Array JSON and fixed-width delta binary are generic controls, not named mod share formats.

The control report's source hash, route count, point count and per-index point counts match the benchmark. All four totals equal their row sums. These controls are source-weighted; they do not independently establish deduplicated or short-route results.

## Constraints preserved from rejected alternatives

Earlier candidate ideas exposed real integration traps that the submitted patch avoids:

1. Passing original routes to general kind 0 with `BARE_COORDINATES` would retain group names, persistent flags and required subwaypoint precision. A standalone reproduction confirmed that bare kind 2 discarded those fields while general kind 0 retained them. A different bare fallback would need a fresh normalized coordinate-only group.
2. Kind-1 no-names decoding recomputes a Rice/quotient semantic winner through the shared compression chooser. Expanding that shared chooser could reject historical bodies. A different outer DEFLATE stream carrying the same selected semantic was accepted; an alternative coordinate semantic was rejected. The submitted change leaves this path untouched.
3. Bare-pack children use a canonical raw-byte Rice/quotient choice with Rice winning ties. It must not be replaced by a whole-frame character heuristic. Kind-5 accepts either local spelling, but no kind-5 or pack changes are submitted.
4. The envelope already consists of one transmitted header byte plus two CRC bytes, in addition to the external `WP:` prefix. Removing these fields, counts or required descriptors would require a wire change. Complete final text remains the scoring unit.

Thirty separate quotient round trips at counts 2, 3, 127, 128, 1,023 and 1,024 covered coordinate extrema, sparse large jumps, local walks, arbitrary supported coordinates and constant axes. All passed. The existing count, coordinate, unary and combinatorial work limits remain unchanged.
