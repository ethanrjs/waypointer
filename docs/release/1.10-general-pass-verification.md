## Measured CPU work

The chat scanner now caches only immutable classification results (including
invalid results), never mutable decoded routes. The synchronized LRU holds at
most 128 exact keys of at most 256 characters. Tests exercise positive/negative
reuse, access-order eviction, key limits, and concurrent miss deduplication.
Wire encoding, decoding acceptance, and suffix trimming are unchanged.

The local Java 25 probe used `-Xmx256m`, five warmups and 20 timed scans per size.
Each message repeated the same valid share three times; every result contained
three matches. Coordinates were deliberately repetitive to exercise large
decoded payloads that fit the chat length limit. The baseline used the unchanged
RC's compiled classes; the candidate used this branch's compiled classes on the
same host. These small samples measure warm repeated-share CPU work, not cold
decoding, whole-client frame time, or GPU performance.

| Decoded points | Code characters | Before median / p95 (ms) | After median / p95 (ms) |
| ---: | ---: | ---: | ---: |
| 100 | 18 | 0.262 / 0.294 | 0.013 / 0.024 |
| 10,000 | 19 | 2.730 / 2.859 | 0.006 / 0.008 |
| 50,000 | 52 | 6.091 / 7.034 | 0.018 / 0.021 |

The paint-cache regression workload fills 256 entries, then requests one new
paint followed by 255 surviving paints. The production eviction policy retains
the survivors and requires one new creation; the prior blind eldest eviction
cascaded through 256 creations. Tests also cover reservation shrink and reset.
This is deterministic cache work evidence, not a measured live texture-upload
or FPS result.
