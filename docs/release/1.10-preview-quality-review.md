# 1.10 export route preview review

## Result and scope

The preview starts at its fitted scale instead of enlarging that fit by 10%, so
long routes retain their endpoints throughout the orbit. Exact cube picking no
longer falls back to empty rectangular corners; small hover targets and actual
billboards keep their larger hit regions. Outline ribbons now respect the 1 px
physical floor instead of inheriting the connector's 1.5 px floor.

Scene construction computes route ordinals in one pass instead of repeatedly
scanning the route. Paint is uploaded only when a visible, nonempty, nonsimplified
preview first renders. Identical paint reuses the active atlas across route
navigation. Hiding retires the atlas with the existing two-frame delay; deferred
render states retain their immutable scene and resource entry. The containing
export screen still advances retirement while its preview is hidden.

The scene and atlases remain cached between ordinary frames. Animated geometry
still uses the existing Minecraft picture-in-picture passes; this change does
not claim to introduce a retained GPU mesh for the preview. Both target adapters
continue to consume the shared ordered pass plan.

## Measured scene construction

Measured on 2026-09-04 with Java 25, using the existing compiled 26.2 baseline at
`1ea7d084ad29bbd67667e251b37eeec482c903b2` and the changed preview classes ahead of
that same dependency classpath. Each size receives 3 warmups and 7 measured
builds; values are medians. Fixtures contain manually colored main waypoints at
`(i, i % 7, i % 13)` in sequence mode. Route creation, GPU upload, and rendering
are excluded. Baseline and changed runs use separate JVMs. This is a small CPU
experiment, not JMH or a frame-rate claim.

| Markers | Baseline median | Changed median |
| --- | ---: | ---: |
| 1,000 | 1.728 ms | 1.102 ms |
| 10,000 | 128.664 ms | 2.934 ms |
| 30,000 | 1,062.876 ms | 4.706 ms |

The checked-in harness is
`tools/preview-experiments/route-preview/RoutePreviewSceneBenchmark.java`.
Generate a runtime classpath in each baseline/changed checkout with the existing
`writeCodecExperimentClasspath` Gradle task after selecting the same Minecraft
target, then run the same harness against each classpath, with Java 25 on PATH:

```sh
./gradlew writeCodecExperimentClasspath -Pminecraft_version=26.2 --no-daemon --max-workers=1
bash tools/preview-experiments/route-preview/run.sh build/reports/codec-experiment-classpath.txt
```

For a baseline checkout that predates the harness, run the changed checkout's
script with the baseline's absolute classpath-file path. The script creates and
removes an isolated temporary compilation directory. No benchmark classes or
machine-specific classpaths belong in the repository.

## Behavioral checks and test pruning

The preview package now has 40 test methods, down from 42. Five methods were
removed or replaced:

- The three constant/identity-only render checks
  `connectorAndOutlineWidthsUsePhysicalPixelFloors`,
  `previewPaintAtlasKeepsReplicatedPaddingDimensions`, and
  `paintedSurfaceUsesACompatibleNoDepthPipelineWhenSelfOcclusionIsDisabled`.
- `simplifiedMarkersUseTheSameReadableDisplayScale`, which repeated the regular
  display-scale calculation without exercising billboard rendering.
- `sceneConstructionForOneThousandWaypointsStaysWithinBudget`, a machine-sensitive
  50 ms timeout. The standalone measurement above replaces that timing claim.

Three meaningful behavior methods replace them: emitted geometry remains inside
the default viewport throughout the orbit at GUI scales 1/2/4; emitted connector
and outline widths stay distinct at those scales; and sequential numbering
matches the route across main/child blocks and load modes. The existing pick
regression also checks an empty cube corner. The ordered pass test is retained
as `depthPrecedesSurfacesAndOutlinesInThePassPlan`; it verifies compositing order
without claiming to execute the adapters.

Standalone compilation and JUnit execution against the 26.2 dependencies passed
all preview tests. Running the changed tests against baseline production classes
produced the expected failures: actual clipping at yaw 75 degrees, a 1.5 px
outline where 1 px was requested, an empty cube corner selecting a waypoint, and
the two old 1.10-zoom expectations.

## Proof limits

These checks execute CPU geometry emission, fit and picking calculations, scene
construction, and widget/control policies. They do not launch Minecraft or prove
interactive GPU output, live pointer behavior, texture-manager failure recovery,
or deferred GPU resource lifetime under load. Lazy upload and two-frame retirement
were verified by ownership/lifecycle review; no GPU allocation counter was
measured. Parent release validation supplies the integrated Gradle/target build
results separately.

Route-specific paint retains precedence over the ordinary global box style.
The separate global sequence-role-color setting intentionally replaces some
sequence paint with role colors in world rendering; this review preserves that
existing behavior, while the export preview shows the route's stored appearance.
